Notation and Terminology¶

This documentation follows the notation used in the HONU, IPLNA, and Learning Entropy publications. Scalar variables are written as italic symbols, for example \(x\), \(y\), \(e\), and \(k\). Vectors are written as bold lowercase symbols, for example \(\mathbf{x}\), \(\mathbf{w}\), and \(\Delta\mathbf{w}\). Matrices are written as bold uppercase symbols, for example \(\mathbf{X}\), \(\mathbf{W}\), and \(\mathbf{C}\). The discrete-time or sample index is \(k\), and \((\cdot)^T\) denotes transposition.

Core LNU notation¶

For the linear neural unit (LNU), the input vector, the weight vector, and the neural output are denoted by

\[\mathbf{x}(k)=\begin{bmatrix}x_0(k)&x_1(k)&\cdots&x_n(k)\end{bmatrix}^T,\]
\[\mathbf{w}(k)=\begin{bmatrix}w_0(k)&w_1(k)&\cdots&w_n(k)\end{bmatrix}^T,\]

and

\[\tilde{y}(k)=\mathbf{w}^T(k)\mathbf{x}(k).\]

The measured or target value is denoted by \(y(k)\). The model residual used for learning is

\[e(k)=y(k)-\tilde{y}(k).\]

In the PID simulation module, the control-loop regulation deviation is written as \(e_c(k)=d(k)-y(k)\), where \(d(k)\) is the desired value and \(y(k)\) is the controlled output. The subscript distinguishes the control-loop regulation deviation from the LNU model residual.

Weight increments and LE notation¶

The weight increment between two consecutive runs, windows, or cycles is

\[\Delta\mathbf{w}^{(j)}=\mathbf{w}^{(j)}-\mathbf{w}^{(j-1)}.\]

Learning Information is denoted by \(L(k)\) when it refers to the novelty of an individual sample or learning step. Approximate Individual Sample Learning Entropy is denoted by \(AISLE(k)\) when the individual-sample approximation is emphasized. Learning Entropy over a frame or interval is denoted by \(LE\) and may be interpreted as an aggregation of \(L(k)\), for example

\[LE \approx \frac{1}{N}\sum_{k=1}^{N}L(k).\]

In this software, the practical LE-like score is computed from the magnitude or unusualness of \(\Delta\mathbf{w}\). Thus, LE is not interpreted as a Shannon-probability measure. It is interpreted as a learning-based novelty measure derived from the effort needed to adapt the local dynamic model.

Practical variable names in code¶

Some Python variables are kept short for compatibility with existing scripts and stored files. For example, W in code may store a matrix of run-wise weight vectors and corresponds to \(\mathbf{W}\) in the documentation. Similarly, dW corresponds to \(\Delta\mathbf{w}\) or to a matrix of such increments depending on context. The scientific notation in this documentation is authoritative; the code names are preserved for backward compatibility.
